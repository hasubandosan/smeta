# Журнал изменений

Формат: новые версии сверху. Версия в `APP_VERSION` (app.js) должна совпадать с верхней записью.
Каждое изменение проекта (человеком или ИИ-агентом) обязательно добавляет запись сюда — см. правила в `AGENTS.md`.

Шаблон записи:

```
## X.Y.Z — ГГГГ-ММ-ДД — кто (человек / название ИИ)
### Добавлено / Изменено / Исправлено / Удалено
- что и зачем (одна строка на пункт)
### Данные
- изменилась ли схема данных и что делает migrate()
### Проверка
- как проверено (tests/smoke.js, вручную)
```

## 0.8.0 — 2026-10-08 — Claude
### Добавлено
- `new.html` + `js/ui.js`: рабочее приложение на новой модели — вкладки Объект / Технологии / Материалы / Смета / Закупка. Правка стен, углов, проёмов, помещений; технологии с операциями, параметрами, материалами и формулами; план работ; смета; закупка (нужно, потери, запас, куплено, докупить, упаковки).
- `js/estimate.js`: расчёт сметы и закупки; неизвестное не превращается в 0, показывается «?» и причина.
- Короб в тестовой ванной (0.6×0.4×2.7 м, условно).
- Тесты: смета/закупка (`core.test.js`, 18) и `tests/ui.test.js`.
### Данные
- Хранилище `stroysmeta:model` (+ `:backup` при каждой загрузке). Старый `stroysmeta:v3` не затронут.
### Проверка
- `node tests/core.test.js`, `node tests/ui.test.js`, `node tests/smoke.js`.

## 0.5.0 — 2026-10-08 — Claude
### Добавлено
- Помещения внутри объекта (длина, ширина, высота, проёмы). Из них автоматически считаются `floor`, `ceiling`, `perimeter`, `walls`; ручные значения этих параметров при наличии помещений не используются.
- Привязка этапа к отдельным помещениям (кнопка 🏠 в списке работ объекта): объём этапа считается только по выбранным комнатам.
- Итог сметы: запас материалов %, накладные %, скидка %, НДС %. Значения по умолчанию для новых объектов — на вкладке «Данные».
- Облачная синхронизация через приватный GitHub Gist (токен с правом gist, хранится только в localStorage браузера). Автоотправка, проверка при запуске, обработка конфликта.
- Локальные точки отката (5 последних, не чаще раза в 5 минут и перед опасными операциями).
- Excel: строки накладных/скидки/НДС/«К ОПЛАТЕ», лист «Помещения».
- `AGENTS.md` (руководство для ИИ-агентов), `CHANGELOG.md`, `tests/smoke.js`.
### Изменено
- Список объектов показывает итог «К оплате».
- Расчёт строки: материалы и расходники умножаются на `1 + запас/100`; в закупку идут те же количества.
### Данные
- Новые поля: `S.finDefaults`, `S.updated`, `S.version`, у объекта `rooms[]`, `fin{}`, у выбора этапа `sel[id].rooms[]`. Добавлен параметр `ceiling`. `migrate()` дополняет старые данные сам.
### Проверка
- `node tests/smoke.js` (jsdom); облачная часть проверена на имитации GitHub API.

## 0.4.0 — 2026-10-08 — Claude
### Изменено
- Модель данных стала набором сущностей вместо markdown-заметок: инструменты, материалы, композиты, дерево этапов (технологий) с ветвлением (`mode: 'choice'`) и шагами, параметры расчёта.
- У этапа: единица, цена работы, формула объёма по умолчанию, материалы с расходом-формулой (в формулах доступны параметры, например `19*thickness/10*1.1`), инструменты, пункты «Условие / Ошибка / Приёмка / Заметка».
- Объект: значения параметров, отмеченные этапы (`sel`), выбор варианта (`pick`), дополнительные позиции (`extra`). Смета, закупка с округлением по упаковкам, список нужных инструментов.
- Импорт .md из Obsidian разбирает файлы в пункты и инструменты; вложенность по номеру в названии файла.
### Данные
- Ключ localStorage `stroysmeta:v3`; старые данные (`v2`, markdown-заметки, `items`) переносятся в `migrate()`.
