# Решения CAD-модуля
- **P1 · drawing хранит `src` + производное.** Каждая запись геометрии лежит целиком в `src`, производные поля (вершины, концы стен/проёмов, площадь) считаются и не сохраняются. Так неизвестные поля не теряются, а id не меняются (контракт, раздел 2; D4).
- **P2 · Правка вершин пересчитывает только `len/turn`.** Значения в пределах допуска (1e-9 м, 1e-7°) остаются как были, поэтому правка и возврат вершины дают исходные числа, а round-trip без правок — побитово тот же JSON. Поворот последней стены не пересчитывается (контур замыкается, контракт раздел 2). Правки округляются до 1e-9, чтобы контур оставался замкнутым для `SM.geo.polygon` (допуск 1e-6 м).
- **P3 · Допуск привязки к вершине (по умолчанию 0,1 м) — параметр интерфейса, не строительная норма.** Шаг сетки по умолчанию не задан (`null`).
- **P4 · Отдача геометрии только через `finish`.** `ok === true` по `SM.geo.validate` обязателен (контракт, раздел 4); при ошибке возвращается `geometry: null` и список замечаний.
- **P5 · Чертёж перерисовывается целиком при каждом изменении вида** (координаты в пикселях, без `transform`), поэтому линии и текст не масштабируются вместе с планом. Перерисовка склеивается через `requestAnimationFrame`. Для разумных планов этого хватает; оптимизация — когда понадобится.
- **P6 · Стена с известной толщиной рисуется полосой по оси контура** (на какую сторону уходит толщина — неизвестно, не выдумываем). Неизвестная толщина = тонкая линия 2 px.
- **P7 · Незамкнутая комната рисуется пунктиром; с неизвестной длиной (`vertices = null`) не рисуется**, замечание приходит через `onIssues` (`SM.geo.validate`).
- **P8 · Допуск привязки, шаг сетки и пределы масштаба — параметры интерфейса, не нормы.** Масштаб ограничен только от вырождения (0,01…100000 px/м).
