# Архитектура (как мы реализуем ТЗ)

Читать после `AGENTS.md`. ТЗ — `PRODUCT_SPEC.md`. Спорные места и принятые решения — `DECISIONS.md`. Что готово — `ROADMAP.md`.

## Состояние на сейчас
Есть **старое приложение v0.5** (`app.js`, `style.css`, `index.html`): дерево этапов + сметы. Оно соответствует ТЗ только частично и будет **заменено новой моделью** (Фаза 11 переносит его данные и функции). До тех пор оно остаётся рабочим, чтобы не терять данные пользователя. **Новый код пишем в `js/` и не дописываем в `app.js`**, кроме подключения.

## Принципы (кратко, подробно в ТЗ §26)
- Без сборки и без ES-модулей (они не работают с `file://`): классические `<script>`, общий глобал `SM`; каждый файл в `js/` — самодостаточный, работает и в браузере, и в Node (`module.exports`), чтобы тестироваться без DOM.
- **Доменная логика не знает про DOM.** UI только показывает и вызывает функции `SM.*`.
- Всё производное считается (`deriveRoom` и т.п.), не хранится.
- Неизвестное = `null`. Никогда не превращать в 0. Расчёт с неизвестным входом возвращает «неизвестно + чего не хватает».
- Ссылки по `id`. Никаких лимитов на число стен/уровней/операций.
- Данные — JSON с `schemaVersion`; любое изменение схемы = миграция + бэкап (ТЗ §23).

## Геометрия (принято)
`model = {walls:[{id,len,turn?,height?,name?,material?}], openings:[{id,wallId,kind,w,h}], rooms:[{id,name,height,wallIds:[…]}]}`.
Помещение — упорядоченный контур стен; у стены длина и поворот в конце (+90 влево, −90 вправо, по умолчанию 90°). Координаты выводятся «черепашкой», поэтому правка длины пересчитывает всё. Незамкнутый контур → площадь `null` + причина. Перегородки, короба, ниши, зоны, общие стены между комнатами — следующими шагами Фазы 2 (как отдельные сущности со ссылками на стены).

## Формулы (принято)
Текст как у пользователя → AST (`SM.parse`) → значение (`SM.evalAst`). Неизвестная переменная → `null`, имена собираются в `missing`. `SM.explain` строит объяснение с подставленными числами. `eval`/`new Function` запрещены. Единицы пока метки + таблица пересчёта (Фаза 6).

## Тесты
`node tests/core.test.js` — домен без DOM, без зависимостей. `node tests/smoke.js` (нужен `npm i jsdom`) — дымовой тест старого UI. **Каждая новая логика — с тестом.**
