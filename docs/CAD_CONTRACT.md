# Контракт CAD-модуля (2D-планировщик) ↔ движок «Помощник строителя»

Версия контракта: **1** (меняется только добавлением полей; ломающие изменения — новая версия и миграция). Статус: CAD-модуль разрабатывается отдельно, подключается к приложению позже (Фаза 10, решение D35).

## 1. Что такое CAD-модуль
Редактор геометрии объекта (`object.geometry`) в виде SVG-чертежа: рисует и правит стены, помещения, проёмы, перегородки, сантехнику; показывает размеры. **Он не источник истины и не хранит свои данные**: всё, что он создаёт, — это `object.geometry` в формате ниже. Сметы, правила, технологии, справочник, облако, точки отката — не его дело и ему недоступны.

## 2. Формат геометрии (источник истины — `js/geometry.js`)
Единицы: метры, градусы. Неизвестное = `null` (не 0). Все `id` — строки (`SM.uid()`), стабильные: CAD не меняет id существующих объектов.
```
geometry = {walls:[], openings:[], rooms:[], fixtures?:[]}
wall    = {id, len, turn?, height?, name?, material?, thickness?, shared?}
opening = {id, wallId|null, roomId?, kind, w, h, at?, sill?, swing?, area?}
room    = {id, name, type?, height, wallIds:[id,...], pos?}
```
**Помещение — замкнутый контур «черепашкой» (D4)**: `wallIds` по порядку обхода; старт (0,0), курс вдоль +X; каждая стена продвигает точку на `len` по текущему курсу, затем курс += `turn` (+90 = влево/против часовой при оси Y вверх; по умолчанию 90; `null` = 90). Поворот последней стены не используется (контур замыкается). Площадь — по формуле Гаусса. В SVG ось Y вниз — CAD отражает сам. Точный расчёт — `SM.geo.polygon(model, room)` (возвращает `pts`), производные — `SM.geo.deriveRoom`. Эталон: `SM.seeds.bathroom().geometry` (6 стен, пол 15,75 м²).
- Координаты вершин **выводятся**, не хранятся. CAD вычисляет их из `len/turn` и обратно переводит правки вершин в `len/turn` (произвольные углы допустимы, не только 90°).
- Каждая комната владеет своими стенами. Общая стена двух комнат = две записи `wall` (по одной в каждой комнате; отделка считается по каждой стороне отдельно), связанные необязательным `shared: <id другой стены>`.
- Проём: `wallId` — стена, на которой он стоит; `null` допустим (старые данные, «проём без привязки», тогда нужен `roomId`). CAD должен уметь привязать такой проём к стене.

## 3. Необязательные поля, которые CAD может добавлять
Движок их сохраняет при загрузке/сохранении/откате (неизвестные поля не теряются), но расчёты пока их **не используют**. Не заполнено = `null`/отсутствует.
| Поле | Смысл |
|---|---|
| `wall.thickness` | толщина стены, м (для отрисовки; расчёты по ней не идут) |
| `wall.shared` | id парной стены соседней комнаты |
| `opening.at` | расстояние от начала стены (по обходу) до ближнего края проёма, м |
| `opening.sill` | высота подоконника/низа проёма от пола, м |
| `opening.swing` | `'in'` / `'out'` / `'sliding'` / `null` — как открывается |
| `room.pos` | `{x, y, rot}` положение локальной системы комнаты на общем плане (м, градусы); без него комнаты не привязаны друг к другу |
| `geometry.fixtures[]` | сантехника и крупные предметы: `{id, roomId, kind, name?, x, y, rot, w, d, h?}`; x,y — центр в локальных координатах комнаты (м), `rot` — градусы, `w×d` — габариты. `kind` — свободная строка (`'toilet'`, `'sink'`, `'bath'`, `'shower'`, `'washer'` …); список — настройка CAD, не норма |

Новые поля, не описанные здесь, CAD вводит только через запрос (раздел 7).

## 4. Что гарантирует движок (CAD может опираться)
- `SM.geo.validate(geometry)` → `{ok, issues:[{level:'error'|'warn'|'info', code, text, id}]}` — единый валидатор. **CAD обязан отдавать только геометрию с `ok === true`.** Коды: `no_id, dup_id, bad_len, bad_turn, opening_wall, opening_room, not_closed, unknown_len, self_intersect, opening_out, opening_loose`. Исполняемая спецификация — `tests/geo.test.js`.
- `SM.geo.polygon`, `SM.geo.deriveRoom`, `SM.uid()`, `SM.isUnknown(v)`, `SM.seeds.bathroom()` (тестовые данные).
- Загрузка/сохранение геометрии — на стороне приложения; `SM.model.migrate` ничего не теряет.
- Любая подмена данных проекта проходит через точку отката (D19) — это делает приложение, не CAD.

## 5. Публичный API CAD-модуля (что реализует CAD; один глобал `SM.planner`)
```
SM.planner.VERSION  // строка версии модуля
SM.planner.CONTRACT // 1
// Чистое ядро (без DOM, тестируется в Node):
SM.planner.fromGeometry(geometry) -> drawing     // вершины/стены/проёмы/предметы в метрах, ось Y вверх
SM.planner.toGeometry(drawing, baseGeometry) -> geometry  // id сохраняются, неизвестные поля baseGeometry копируются
// Интерфейс (SVG):
const h = SM.planner.mount(el, {geometry, readOnly, onChange, onSelect, onIssues})
h.setGeometry(g)  h.getGeometry()  h.select(ids)  h.focus(roomId)  h.setReadOnly(bool)  h.undo()  h.redo()  h.destroy()
```
- `onChange(newGeometry, meta)`: вызывается после каждого завершённого действия (не на каждый пиксель перетаскивания). `newGeometry` — полная копия, прошедшая `validate`. `meta = {reason, added:{walls,openings,rooms,fixtures}, removed:{…}, changed:{…}}` — списки id. Если `onChange` вернул `false` — приложение отклонило изменение, CAD откатывает его.
- CAD не обращается к `localStorage`, `fetch`, глобальным данным приложения; всё получает через `opts` и пишет только через `onChange`.
- Отмена/повтор (undo/redo) — внутри CAD; история не сохраняется в проект.

## 6. Что делает приложение (хозяин), не CAD
- Поверхности (`object.surfaces`: пол/потолок/стены комнаты) и привязка состояний/целей — приложение создаёт и согласует по `roomId`/`wallId` после `onChange` (отдельный срез «поверхности из геометрии»). CAD про поверхности не знает.
- Подключение: тег `<script>` в `index.html`, вкладка/кнопка, передача геометрии и приём `onChange`. Делается после того, как CAD готов по UI и функционалу.
- Сантехнические нормы и зазоры (расстояние перед унитазом и т. п.) в расчёты не подставляются; если CAD показывает предупреждения по зазорам, числа вводит человек (значение по умолчанию — неизвестно), выдумывать нельзя.

## 7. Как менять контракт
CAD-бот не правит этот файл сам: новые поля/функции он описывает в `docs/CAD_CONTRACT_REQUESTS.md` (что нужно, зачем, пример данных). Основной бот отвечает и обновляет контракт. Совместимость: новое поле всегда необязательное, старые данные без него обязаны работать.

## 8. Известные ограничения движка (CAD на них не рассчитывает)
Нет многоуровневости (этажей), нет расчёта по толщине стен и общим стенам, нет редактора привязки проёмов к стенам в основном UI (его даст CAD), процессы применяются ко всем стенам помещения (выбор стен не сделан), «санузловые» процессы (сантехника, электрика) в библиотеке ещё не добавлены.
