# Запросы CAD-модуля к контракту
Формат записи: что нужно · зачем · пример данных. Отвечает основной бот.

## 1. `opening.hinge` — сторона петель
**Что:** необязательное поле проёма `hinge: 'start' | 'end' | null` — у какого конца проёма (по обходу стены) шарнир двери.
**Зачем:** дуга открывания рисуется правильной стороной; сейчас шарнир условно у начала (P17).
**Пример:** `{id, wallId, kind: 'дверь', w: 0.9, at: 0.5, swing: 'in', hinge: 'end'}`. Без поля — как сейчас (неизвестно, рисуем у начала).

## 2. `fixture.front` — лицевая сторона предмета
**Что:** необязательное поле предмета `front: '+y' | '-y' | '+x' | '-x' | null` — в какую сторону (в осях предмета до поворота) он «смотрит».
**Зачем:** проверять свободное место «перед предметом» (унитаз, раковина, духовка) и рисовать лицевую сторону. Сейчас зазоры считаются только между предметами (P24).
**Пример:** `{id, roomId, kind: 'toilet', x: 0.4, y: 0.3, rot: 0, w: 0.4, d: 0.7, front: '+y'}`. Без поля — лицевая сторона неизвестна, как сейчас.

## 3. (от основного приложения, при подключении v0.29) `onChange`: отказ и состав изменений
**Что:** (а) по контракту §5 `onChange` может вернуть `false` — CAD откатывает правку; в `planner-ui.js` v0.7.0 возвращаемое значение не учитывается. (б) `meta` содержит только `{reason}`, без списков `added/removed/changed` по id. (в) `removeRoom` на помещении с проёмами сам отказывает («Проём … ссылается на несуществующее помещение») — удалить помещение с дверью нельзя.
**Зачем:** (а) приложение запрещает убрать помещение, у которого есть работы/цели/состояние; сейчас оно откатывает через `undo()` с задержкой в 0 мс — работает, но с миганием. (б) показывать «убрано помещений: N» без собственного сравнения. (в) удобство.
**Пример:** `onChange(g, meta) === false` → CAD сам делает откат, `h.undo()` не нужен. Пока приложение обходится без этого — запрос не срочный.

## 4. (от основного приложения, v0.31) Уточнить роль `wall.thickness`
**Что:** в `CAD_CONTRACT.md` у `wall.thickness` написано «для отрисовки; расчёты по ней не идут». С v0.31 основное приложение считает по ней площадь откосов проёмов (`reveals` = полный периметр проёма × толщина стены, D43); длины стен по-прежнему внутренние размеры.
**Зачем:** чтобы CAD-бот не менял смысл `thickness` (например, на толщину «по осям») и знал, что значение попадает в смету.
**Пример:** строка в таблице §3: «`wall.thickness` — толщина стены, м; отрисовка и площадь откосов (приложение)».

## 5. (от основного приложения, v0.32) Пипетка свойств стены на чертеже
**Что:** в панели выбранной стены — режим «пипетка»: взять свойства (`material`, `thickness`) одной стены и применить кликом к другим стенам (в том числе нескольким подряд, в том числе другой комнаты). Результат — обычная правка `onChange`.
**Зачем:** в приложении такая пипетка уже есть (вкладка «Объект»); на чертеже стены выбираются мышью, там это естественнее. У общей стены (`shared`) приложение само выровняет вторую сторону.
**Пример:** выбрана стена → «Пипетка» → клики по стенам → «Готово»; одна запись в истории отмены.

## 6. (от основного приложения, v0.32) Перетаскивание проёма между стенами
**Что:** дверь/окно можно перетащить курсором на другую стену (своей или соседней комнаты), а не только двигать вдоль своей оси: меняются `opening.wallId` (и `roomId`, если проём перенесён в другую комнату), положение вдоль новой стены.
**Зачем:** сейчас проём привязан к стене и двигается только по оси; на практике проём часто переносят на соседнюю стену.
**Пример:** `onChange` с проёмом, у которого сменился `wallId`; если на новой стене проём не помещается — отказ с причиной.
