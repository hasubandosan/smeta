# CAD-планировщик: как устроен модуль
Версия модуля: `SM.planner.VERSION` (см. `PLANNER_CHANGELOG.md`). Контракт: `CAD_CONTRACT.md` (версия 1). Решения: `PLANNER_DECISIONS.md`.

## Файлы
- `js/planner.js` — чистое ядро, без DOM, тестируется в Node (`tests/planner.test.js`).
- `js/planner-ui.js` — интерфейс (SVG), `SM.planner.mount`; `planner.html` — отдельная страница-стенд (открывается с file://, подключает core, geometry, model, seeds и файлы планировщика). Тест: `tests/planner-ui.test.js` (нужен jsdom).

## Ядро (срез 1)
`drawing = {rooms, walls, openings, fixtures}`. У каждой записи: `id`, `src` (полная копия записи геометрии, включая неизвестные поля) и производные поля (не сохраняются): у комнаты `vertices, closed, area, perimeter, issue`; у стены `roomId, a, b`; у проёма `p1, p2` (концы по `at`/`w`, иначе `null`). Координаты в метрах, Y вверх, локальные для комнаты (`room.pos` — положение на плане, см. `toWorld`).

| Функция | Что делает |
|---|---|
| `fromGeometry(g)` | геометрия → drawing; вход не меняется; неизвестная длина/незамкнутый контур не ломают загрузку (`vertices = null`, `issue` по-русски) |
| `toGeometry(drawing, base)` | drawing → новая геометрия; id и неизвестные поля сохраняются; `len/turn` пересчитываются только если вершины реально сдвинуты |
| `moveVertex(drawing, roomId, i, pt)` | новый drawing с пересчитанными `len/turn` соседних стен; бросает понятную ошибку, если контур править нельзя |
| `snapPoint(drawing, pt, {grid, tol, roomId})` | привязка: вершина, затем сетка; `grid` не задан → точка как есть |
| `finish(drawing, base)` | `{ok, geometry, issues}`; `geometry` отдаётся только при `SM.geo.validate(...).ok` |
| `measure(g)` | пол/периметр по комнатам (через `SM.geo.deriveRoom`) |
| `describe(g, id)` | текст для панели свойств: `{kind, title, rows}`; неизвестное — «не задано» |
| `vertexAngle(d, roomId, k)`, `nearestOnContour(d, roomId, pt, vtol)`, `toLocal` | внутренний угол в вершине; ближайшая точка контура (с привязкой к вершине); обратное к `toWorld` |
| `ops.*` | правка, см. ниже |
| `createHistory(g)` | undo/redo снимками без лимита глубины; в проект не попадает |

Положение комнаты на плане: при выдаче геометрии (`toGeometry`) локальная система комнаты снова начинается с первой вершины вдоль +X, а поворот и сдвиг уходят в `room.pos`; координаты предметов пересчитываются, чтобы всё оставалось на месте (P2, P9). `pos` появляется, только если он нужен.

## Правка (срез 3): `SM.planner.ops`
Все операции — `(drawing, …) → новый drawing`, вход не меняется, ошибки — `Error` по-русски. Дополнительно у результата: `notes` (предупреждения), `created` (id созданного).
| Операция | Что делает |
|---|---|
| `moveVertex(d, roomId, i, pt)` | угол в локальные координаты, пересчёт `len/turn` |
| `setWallLength(d, wallId, len, {anchor, mode})` | длина числом. `anchor`: `'start'` (двигается конец) или `'end'`; `mode`: `'push'` (соседняя стена сдвигается целиком, прямые углы сохраняются) или `'end'` (меняется только угол) |
| `setVertexAngle(d, roomId, k, deg)` | внутренний угол: прямой — 90°, Г-образный внутренний — 270°; поворачивается следующая стена, её длина сохраняется |
| `splitWall(d, wallId, at)` | разделить на расстоянии `at` м (пусто — пополам); первая часть сохраняет id; проёмы переезжают на свою часть |
| `removeVertex(d, roomId, k)` | убрать угол: стены при нём сливаются (остаётся стена, что приходит в угол); меньше трёх стен нельзя |
| `setWallProps`, `setRoomProps` | название, материал, толщина, высота, тип; пусто = неизвестно (`null`) |
| `addRoomRect`, `addRoomL`, `addRoomFromPoints` | новая комната; высота и прочее неизвестное = `null` |
| `splitRoom(d, roomId, pA, pB, {names, thickness})` | перегородка: комната режется на две между двумя точками контура; хорда — по своей стене в каждой комнате, связанные `shared` |
| `removeRoom(d, roomId)` | удалить помещение; проёмы остаются без привязки, предметы удаляются (в `notes`) |

## Интерфейс
`const h = SM.planner.mount(el, {geometry, readOnly, grid, onSelect, onChange, onIssues})` рисует SVG: сетку (шаг подбирается по масштабу), помещения с названием и площадью, стены (толщина, если известна; иначе тонкая линия), длины стен снаружи контура, проёмы на стенах (дверь/окно по `kind`), предметы. Проёмы без стены и без `at` не рисуются (они в списке «без привязки» на стенде). Предмет без `w`/`d` — маркер, размеры не выдумываются.
Управление: мышь и касание — сдвиг перетаскиванием, колесо/щипок — масштаб, клик/тап — выбор (Shift — добавить к выбору), кнопки «+», «−», «⤢».
`h`: `setGeometry, getGeometry, select(ids), selected, focus(roomId), fit, zoomIn, zoomOut, setReadOnly, isReadOnly, undo, redo, view, flush, destroy`. `select` программно не вызывает `onSelect`. До среза 3 правок нет: `onChange` не вызывается, `undo/redo` возвращают `false`.

### Правка в интерфейсе (`readOnly: false`)
Выберите помещение, стену или угол — внизу панель с полями: длина, угол, толщина, разделение, название, высота. Числа можно вводить через запятую; Enter применяет. Ручки углов у выбранной комнаты перетаскиваются мышью и пальцем (привязка к другим углам и, если задан шаг, к сетке). «＋ Комната» — прямоугольная и Г-образная (рядом с существующими). «Перегородка…» — две точки на стенах. ↶/↷ и Ctrl+Z/Ctrl+Y — отмена и повтор, без ограничения глубины.
Правка принимается, только если геометрия проходит `SM.geo.validate` (`ok`); иначе откат и сообщение («Так нельзя: …»). `onChange(geometry, {reason})` вызывается после каждой принятой правки, отмены и повтора; `onIssues` — следом.
Дополнительно в `h`: `edit(имя, …аргументы)` (любая операция из `ops` с проверкой и историей, возвращает `{ok, message}`), `undo, redo, canUndo, canRedo, setGrid, getGrid, message`. `setGeometry` сбрасывает историю.
