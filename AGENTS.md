# AGENTS.md — руководство для ИИ-агентов и разработчиков

Читайте этот файл первым. После работы обязательно обновите `CHANGELOG.md` (см. раздел 7).

## 1. Что это
«Помощник строителя» — статический веб-приложение (GitHub Pages) для строительных смет. Пользователь описывает **технологии** (дерево этапов с ветвлением, ценой работы, формулой объёма, материалами и инструментами), создаёт **объекты** (параметры, помещения, выбранные этапы) и получает смету: материалы, количества, деньги за материалы и за работу, закупку по упаковкам, нужные инструменты, экспорт в Excel.

Сайт: https://hasubandosan.github.io/smeta/ · репозиторий: hasubandosan/smeta · ветка `main`.

## 2. Принципы и ограничения
- **Без сборки и фреймворков.** Чистый HTML/CSS/JS, три файла: `index.html`, `style.css`, `app.js`. Единственная внешняя зависимость — SheetJS с cdnjs (экспорт Excel). Должно открываться и с `file://`.
- **Данные только в браузере** (`localStorage`), плюс необязательное облако через GitHub Gist (токен пользователя). Никаких серверов и секретов в коде.
- **Интерфейс на русском.** Идентификаторы в коде на английском.
- **Владелец проекта не программист.** Результат работы отдавайте как **git-патч** (`git format-patch -1 --stdout > имя.patch`) и пишите полные команды для PowerShell/VS Code: перейти в папку репозитория, `git apply --check`, `git apply`, `git add -A`, `git commit -m`, `git push`. Патч должен применяться на текущее состояние `main`. Объясняйте простыми словами, без лишнего.
- Экономьте объём: делайте то, что просили, без лишнего.
- Не ломайте данные пользователя: любое изменение схемы сопровождайте миграцией в `migrate()`.

## 4. Модель данных (`S`, localStorage ключ `stroysmeta:v3`)
```
S = {
  materials:  [{id, name, category:'material'|'consumable', unit, price, packQty}]   // цена за упаковку, в упаковке packQty единиц
  composites: [{id, name, unit, components:[{refType:'material'|'composite', refId, rate}]}]
  tools:      [{id, name, note}]
  params:     [{id, key, label, unit, def}]      // общий список параметров: floor, ceiling, walls, perimeter, thickness…
  stages:     [{id, parentId:'' , name, mode:'steps'|'choice', unit, price, vol, components:[…], tools:[toolId], notes:[{id,cat:'cond'|'error'|'accept'|'note',text}]}]
  objects:    [{id, name, note,
                values:{key:value},                 // ручные значения параметров
                rooms:[{id,name,l,w,h,open}],       // необязательно; если есть — floor/ceiling/perimeter/walls считаются из них
                fin:{reserve, overhead, discount, vat},   // проценты
                sel:{stageId:{q?:'формула', rooms?:[roomId]}},   // какие этапы применены
                pick:{choiceStageId: childId},      // выбранный вариант ветвления
                extra:[{id, type:'material'|'composite'|'custom', refId|name,category,unit,price, qty}]}]
  finDefaults:{reserve, overhead, discount, vat}, updated:<ms>, version:'0.5.0'
}
```
- Порядок этапов-соседей = порядок в массиве `stages`.
- `rate` у компонента и `vol`/`q` — **строки-формулы** (`19*thickness/10*1.1`); числа, `+ - * / ( )`, имена параметров; запятая = точка.
- Ключи облака/снимков/токена отдельные: `stroysmeta:sync`, `stroysmeta:snaps`. Токен не входит в `S` и в резервные копии.

## 5. Правила расчёта
- Цена единицы материала = `price / packQty`.
- `cost(type,id,V)` — стоимость 1 единицы **самого** этапа/композита: работа (`price`) + материалы/расходники по его нормам. Дочерние шаги не суммируются: каждый шаг считается отдельной строкой.
- Включённые этапы: `includedNodes(o)` — отмеченные (`sel`) этапы вместе с отмеченными предками; у родителя `mode:'choice'` учитывается только выбранный (`pick`) потомок. Считаются только этапы с `unit`.
- Объём строки: `sel[id].q`, если задан, иначе `stage.vol`. Переменные: `objVars(o, roomIds)` = значения параметров; при наличии помещений ключи `floor, ceiling, perimeter, walls` берутся из `roomsCalc` по выбранным (`sel[id].rooms`) или всем комнатам.
- Запас: материалы и расходники строки умножаются на `1 + fin.reserve/100` (в смету и в закупку). Итог: подытог → `+ накладные%` → `− скидка%` → `+ НДС%` = «К оплате» (`totals()`).
- Закупка (`buyList`): суммирование количества каждого материала по всем строкам, упаковок = `ceil(qty/packQty)`.

## 6. Устройство `app.js`
Порядок разделов: БАЗА (seed, parseNote, migrate, load, save) → РАСЧЁТЫ → ОБЩИЕ БЛОКИ (options, compEditor) → ЭКРАНЫ (`render`, `viewStages/stageDetail`, `viewObjects/objectDetail/pickHtml`, материалы, инструменты, композиты, данные) → ЭКСПОРТ/ИМПОРТ → СНИМКИ И ОБЛАКО → ДЕЙСТВИЯ.
- Состояние интерфейса — объект `ui` (не сохраняется). Любое изменение данных: правим `S`, вызываем `commit()` (= `save()` + `render()`).
- Разметка строится строками-шаблонами; события — делегированием: элемент с `data-act="имя"` вызывает `H[имя]` (клик по не-полям, `change` у input/select). `data-live` — реакция на `input` без перерисовки (`LIVE`).
- Новое действие: добавить кнопку/поле с `data-act`, обработчик в `H`, при необходимости миграцию.
- Не используйте `localStorage` напрямую в обход `save()`; при изменении `S` от «чужого» источника (облако, импорт) вызывайте `snap(true)` до замены и `save({keepStamp:true})` для облака.

## 7. Как вносить изменения
1. Прочитать этот файл и верх `CHANGELOG.md`.
2. Внести изменения в минимальном объёме.
3. Если изменилась структура `S` — обновить `migrate()` и раздел 4 этого файла.
4. Поднять `APP_VERSION` в `app.js` (патч/минор по смыслу) и добавить запись в `CHANGELOG.md` по шаблону (дата, кто, что, данные, проверка).
5. Запустить тесты: `npm i jsdom` и `node tests/smoke.js` (из корня проекта). Добавить проверку для новой логики расчётов.
6. Сформировать патч поверх `main` и выдать пользователю команды применения (см. раздел 2).

## 8. Известные ограничения и очередь задач
Сделано: этапы с ветвлением, формулы, параметры, помещения, запас/накладные/скидка/НДС, закупка по упаковкам, инструменты, Excel, облако (Gist), точки отката, импорт .md.

Идеи на очередь (по приоритету):
1. Печатная смета для клиента (PDF/печать без закупочных деталей) и Excel с живыми формулами.
2. Копирование объекта и этапа; шаблоны объекта (готовый набор отмеченных этапов).
3. Чек-листы приёмки по пунктам «Приёмка» для конкретного объекта; статусы этапов и оплаты.
4. Цены с датой актуальности, несколько поставщиков, массовое обновление цен.
5. Фото и ссылки у этапов, инструментов, материалов.
6. Импорт: распознавание материалов и норм расхода из текста заметок.
7. Редактор ветвления шире: условия вроде «если толщина > 50 мм, нужна сетка».
Ограничение: данные одного браузера, пока не подключено облако; конфликт при одновременной правке с двух устройств решается вопросом «взять облако / оставить локальные».
