# AGENTS.md — читать первым

Проект «Помощник строителя»: универсальный инструмент строителя/прораба (объект → состояние → процессы → технологии → операции → материалы → смета → закупка → выполнение). Сайт на GitHub Pages: https://hasubandosan.github.io/smeta/ · репозиторий `hasubandosan/smeta`, ветка `main`.

Над проектом работают **разные ИИ-боты** по очереди. Всё, что нужно знать, лежит в репозитории. Не полагайся на память чата.

## Порядок чтения (обязательно)
1. Этот файл.
2. `docs/ROADMAP.md` — что готово, что дальше.
3. `docs/ARCHITECTURE.md` — как устроено и как мы это реализуем.
4. `docs/DECISIONS.md` — принятые решения (не отменять молча).
5. `docs/PRODUCT_SPEC.md` — ТЗ владельца, источник истины.
6. Верх `CHANGELOG.md`.

## Как идёт работа
- Владелец — **не программист**, работает в **VS Code** на Windows. Результат отдаётся **git-патчем** (`git format-patch -1 --stdout > имя.patch`), который владелец скачивает и применяет сам.
- Вместе с патчем всегда давай готовые команды для PowerShell: перейти в папку репозитория, `git pull`, `git apply --check имя.patch`, `git apply имя.patch`, `git add -A`, `git commit -m "..."`, `git push`. Патч должен применяться на текущий `main`.
- Пиши по-русски, просто и коротко, без лишних объяснений. Не заставляй владельца разбираться в архитектуре.
- Владелец ожидает **полные рабочие файлы**, а не обрывки и не заглушки.
- Делай вертикальными срезами по фазам из `ROADMAP.md`. Один патч = один законченный срез с тестом.

## Жёсткие правила
- Без сервера, БД и сборки. Чистый HTML/CSS/JS, должно открываться и с `file://` (значит, **без ES-модулей**: классические `<script>`, глобал `SM`).
- Новый код — в `js/`. Домен не знает про DOM. UI только показывает.
- Неизвестное = `null`, не 0. Не выдумывай строительные нормы, цены, упаковки — спрашивай или помечай UNKNOWN.
- Не ломай данные пользователя: изменение схемы = миграция + бэкап. localStorage молча не сбрасывать, облачные данные молча не заменять.
- Никаких искусственных лимитов (число стен, уровней, операций).
- Интерфейс на русском, идентификаторы в коде на английском.

## Перед сдачей патча (всегда)
1. `node tests/core.test.js` и (если трогал старый UI) `node tests/smoke.js` (`npm i jsdom`). Для новой логики — новый тест.
2. Обнови `docs/ROADMAP.md` (статусы), `docs/ARCHITECTURE.md` (если появились модули), `docs/DECISIONS.md` (если принял решение) и **добавь запись в `CHANGELOG.md`** (шаблон там же). Поднять `APP_VERSION` в `app.js`.
3. Выдай патч + команды для PowerShell.
